# Warehouse Master

أيوه، ينفع جدًا تعمل النظام ده على Lovable، والأفضل ما نعملوش مجرد شاشة مخزون؛ نعمل Warehouse Management System (WMS) كامل يدير مخزن رئيسي + 35 مخزن فرعي، مع حركة الأصناف والموافقات والجرد والتقارير والصلاحيات.

وأقدر أجهز لك Prompt واحد شامل تحطه في Lovable، ويكون الأساس لبناء النظام بالكامل.

الهيكل المقترح للنظام

1. لوحة التحكم الرئيسية

* إجمالي المخزون.

* قيمة المخزون.

* المخزن الرئيسي.

* 35 مخزن فرعي.

* الأصناف منخفضة المخزون.

* الطلبات المعلقة.

* التحويلات بين المخازن.

* الوارد والصادر.

* آخر عمليات الجرد.

* آخر حركات المخزون.

* تنبيهات الأصناف التي وصلت للحد الأدنى.

* Dashboard برسوم بيانية.

2. إدارة المخازن

* مخزن رئيسي.

* 35 مخزن فرعي.

* إضافة/تعديل/إيقاف مخزن.

* بيانات المسؤول عن كل مخزن.

* موقع المخزن.

* تقسيم المخزن إلى:

    * منطقة

    * رف

    * ممر

    * خانة / Bin

* معرفة مكان كل صنف بالضبط داخل المخزن.

3. إدارة الأصناف

لكل صنف:

* كود الصنف SKU.

* Barcode.

* الاسم بالعربي.

* الاسم بالإنجليزي.

* التصنيف.

* الوحدة.

* صورة المنتج.

* الحد الأدنى.

* الحد الأقصى.

* المورد.

* سعر الشراء.

* ملاحظات.

* مكان التخزين.

* المخزن الموجود فيه.

* الرصيد الحالي.

* تاريخ الإضافة.

* حالة الصنف Active / Inactive.

مع دعم:

* إدخال يدوي.

* Barcode Scanner.

* استيراد Excel.

* تصدير Excel.

* إضافة صورة.

* تعديل جماعي للأصناف.

4. الطلبات من المخازن الفرعية

المخزن الفرعي يقدر يعمل:

طلب صرف / طلب تزويد

مثلاً:

فرع 12 → يطلب 20 عبوة شامبو من المخزن الرئيسي.

حالة الطلب:

Draft → Pending → Approved → Preparing → Shipped → Received → Completed

مع إمكانية رفض الطلب وإظهار سبب الرفض.

5. التحويل بين المخازن

مش لازم كل شيء يمر على المخزن الرئيسي.

مثلاً:

مخزن فرع 5 → مخزن فرع 18.

ويتم إنشاء:

* Transfer Request

* موافقة

* تجهيز

* إرسال

* استلام

* تأكيد الكمية

* تسجيل الحركة تلقائيًا.

مع إمكانية وجود فرق بين:

الكمية المرسلة والكمية المستلمة.

6. الوارد

إضافة:

* المورد.

* رقم الفاتورة.

* التاريخ.

* المخزن المستلم.

* الأصناف.

* الكمية.

* سعر الشراء.

* الإجمالي.

* Barcode.

* Batch/Lot إذا احتجته.

* تاريخ الصلاحية إذا كان الصنف يحتاج ذلك.

وعند اعتماد الوارد:

يزيد رصيد المخزن تلقائيًا.

7. الصادر

تسجيل:

* الصنف.

* الكمية.

* المخزن.

* الجهة المستلمة.

* سبب الصرف.

* المستخدم.

* التاريخ.

والرصيد ينقص تلقائيًا.

8. الجرد

نظام جرد احترافي:

* جرد كامل.

* جرد جزئي.

* جرد حسب التصنيف.

* جرد حسب الرف.

* جرد باستخدام Barcode.

* إدخال الكميات يدويًا.

* مقارنة الرصيد الدفتري بالفعلي.

* إظهار العجز.

* إظهار الزيادة.

* اعتماد فروقات الجرد.

* سجل كامل لكل عملية جرد.

9. الموردين

ملف كامل لكل مورد:

* اسم المورد عربي/إنجليزي.

* رقم الهاتف.

* البريد.

* العنوان.

* الشخص المسؤول.

* الأصناف التي يوردها.

* أسعار الشراء.

* تاريخ آخر شراء.

* إجمالي المشتريات.

* الفواتير.

* كشف حساب المورد إذا أردت تطوير النظام لاحقًا.

10. التقارير

التقارير ستكون جزء أساسي من النظام، وليس إضافة جانبية:

* تقرير المخزون الحالي.

* تقرير مخزون كل فرع.

* تقرير إجمالي المخزون.

* تقرير حركة صنف.

* تقرير الوارد.

* تقرير الصادر.

* تقرير التحويلات.

* تقرير الطلبات.

* تقرير الجرد.

* تقرير العجز والزيادة.

* تقرير الأصناف الراكدة.

* تقرير الأصناف الأكثر حركة.

* تقرير الأصناف منخفضة المخزون.

* تقرير الموردين.

* تقرير المشتريات.

* تقرير قيمة المخزون.

* تقرير حركة كل مخزن.

* تقرير حركة كل مستخدم.

* تقرير الأصناف ومواقعها.

* تقرير تاريخي لأي صنف.

وكل تقرير:

PDF + Excel + Print

الصلاحيات

نعمل نظام Role-Based Access Control.

مثلاً:

Super Admin

* كل الصلاحيات.

Warehouse Manager

* إدارة المخازن.

* الموافقات.

* الجرد.

* التحويلات.

Main Warehouse

* إدارة المخزن الرئيسي.

* استقبال الطلبات.

* تجهيز الطلبات.

* الصرف.

* الاستلام.

Branch Warehouse

* مشاهدة مخزنه فقط.

* عمل طلبات.

* استلام التحويلات.

* الجرد.

* مشاهدة حركة مخزنه.

Inventory Auditor

* الجرد والتقارير فقط.

Viewer

* مشاهدة فقط.

والأهم:

كل مستخدم يشوف فقط المخازن والعمليات المسموح له بها.

تسجيل العمليات Audit Log

دي مهمة جدًا في النظام المحاسبي والإداري.

كل عملية يتم تسجيل:

* من قام بها.

* التاريخ.

* الوقت.

* العملية.

* الصنف.

* الكمية.

* المخزن.

* القيمة قبل العملية.

* القيمة بعد العملية.

* الجهاز/IP إذا كان مناسبًا.

* سبب التعديل.

ولا يتم حذف حركة مخزون نهائيًا؛ الأفضل عمل Reverse / Adjustment مع الاحتفاظ بالتاريخ.

اللغة

نقطة مهمة جدًا

أنا أنصح أن يكون المخزون مبني على Stock Movements وليس مجرد تعديل رقم الرصيد.

يعني لو عندك:

شامبو = 100

ثم صرفت 20:

Opening 100

Issue -20

Balance 80

ثم استلمت 50:

Receipt +50

Balance 130

وبالتالي تقدر في أي وقت تعرف ليه الرصيد أصبح 130 ومن عمل كل حركة ومتى.
